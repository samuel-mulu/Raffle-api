# Backend Deployment Guide (Render + Prisma)

## Quick Setup with render.yaml

The `render.yaml` file is already configured for automatic deployment. Just push to GitHub and connect to Render.

## Manual Deployment Steps

### 1. Push to GitHub
```bash
git add .
git commit -m "Add render configuration"
git push
```

### 2. Deploy to Render
1. Go to [render.com](https://render.com)
2. Connect your GitHub repository
3. Render will automatically detect the `render.yaml` configuration
4. Click "Deploy"

### 3. Database Setup (After Deployment)
Once deployed, you need to run the database migrations and seed:

**Option A: Using Render Shell**
1. Go to your service dashboard on Render
2. Click "Shell" 
3. Run these commands:
```bash
# Run database migrations
npm run prisma:migrate

# Generate Prisma client
npm run prisma:generate

# Seed the database with test data
npm run prisma:seed
```

**Option B: Using Render Deploy Hooks**
Add these to your render.yaml build command:
```yaml
buildCommand: npm install && npm run build && npm run prisma:generate && npm run prisma:migrate && npm run prisma:seed
```

## Environment Variables (Auto-Configured)
- `DATABASE_URL`: Automatically set by Render from the database
- `JWT_SECRET`: Auto-generated by Render
- `JWT_EXPIRES_IN`: Set to `7d`
- `NODE_ENV`: Set to `production`

## Troubleshooting

### Common Issues
1. **Migration fails**: Check DATABASE_URL format
2. **Seed fails**: Ensure migrations ran first
3. **Build fails**: Check logs for missing dependencies
4. **Connection refused**: Ensure service started correctly

### Database Connection
The DATABASE_URL should look like:
```
postgresql://raffle_user:password@host:port/raffle
```

### Logs
Check Render logs for:
- Build errors
- Database connection issues
- Runtime errors

## Frontend Integration
After backend deployment, update your Vercel frontend:
1. Set `NEXT_PUBLIC_API_URL` to your Render API URL
2. Redeploy the frontend

## API Endpoints
- `POST /auth/login` - Authentication
- `GET /campaigns` - List campaigns
- `GET /admin/campaigns` - Admin campaigns
- `GET /creator/campaigns` - Creator campaigns
- `POST /campaigns` - Create campaign
